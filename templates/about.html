About the Project

A simple Trekking Management Application built for MAD1, designed to make trek browsing, booking, and management easier.

Project Overview

The Trekking Management Application is a web-based system for managing trekking activities in one place. It helps users browse available treks, check important trek details, book their slots, and view their booking history whenever needed.

For the admin, the system makes it easier to manage trek details, users, trek staff, staff approval, and booking records. Trek staff can manage only the treks assigned to them and view participant details for those treks.

The project uses Flask for backend routing, SQLite for storing data, SQLAlchemy for database handling, Jinja templates for rendering pages, and Bootstrap for creating a simple responsive user interface.

Main Roles

Admin

The admin controls the main system activities. Admin can create and manage treks, manage users, approve trek staff, assign staff members to treks, and view booking records.

Trek Staff

Trek staff helps in handling trek-related work after approval from the admin. Staff can manage assigned treks, update trek status, and view participant details for those specific treks.

User / Trekker

Users can register on the application, browse open treks, check trek details like location, difficulty, duration, and slots, book available treks, and view their booking history.

Basic Workflow

Admin first creates trek records with details such as location, difficulty, duration, available slots, and trek status.

Admin approves trek staff and assigns staff members to specific treks so that they can manage only their assigned treks.

Users browse open treks, choose a trek based on their interest, and make bookings if slots are available.

Trek staff manages assigned treks, updates trek information when needed, and checks participant details.

Booking records and trek history are stored in the system so users and admin can refer to them later.
